# Правила проекта PetHelper

## 1. Продукт
PetHelper помогает владельцу собаки или кошки вести домашнее лечение по выписке врача: фото выписки → модель собирает черновик плана (препарат, доза, время, срок) → владелец проверяет → на экране «Сегодня» нажимает «Дал», а помощник видит «Уже дано» и не может отметить приём повторно.
Продукт не ставит диагноз, не заменяет врача и не связан с клиникой. Подробно — в PRODUCT.md.

## 2. Стек и версии
- Next.js 16.4.6, App Router; `dev` и `build` запускаются с `--webpack`. Перед кодом читать гайд в `node_modules/next/dist/docs/` — API отличаются от привычных.
- React 19.2, TypeScript 5.9.
- Tailwind CSS 4: токены (цвета, шрифты, радиусы, тени) — в `app/globals.css` через `@theme`.
- shadcn/ui: компоненты в `components/ui/` на Radix; настройки в `components.json`.
- Supabase JS — данные; миграции в `supabase/migrations/`.
- Vitest 4 — unit-тесты в `tests/unit/`; Playwright — e2e в `tests/e2e/`.
- Node 24 (`.nvmrc`).

## 3. Как запустить и проверить
```text
npm ci                          # установка по lock-файлу
npm run dev                     # http://localhost:3000
npm run typecheck               # tsc --noEmit
npm test                        # vitest run
npm run build                   # продакшен-сборка
npx playwright install chromium # один раз
npm run test:e2e                # поднимает свой сервер на 3100
```
Задача считается готовой, только когда `typecheck`, `test` и `build` проходят, а для пользовательских сценариев — ещё и `test:e2e`.

## 4. Цикл фичи
1. **Спецификация** — файл `docs/specs/<фича>.md` по шаблону `docs/specs/feature-template.md`: что, для кого, сценарий, Дано/Когда/Тогда, чего не делать.
2. **План** — раздел «Принятый план»: какие файлы меняются, какие команды запускаются, какие проверки.
3. **Жду подтверждения** — до одобрения плана человеком код не пишу и команды не запускаю.
4. **Выполнение** — строго по плану; если план нужно менять, сначала спрашиваю.
5. **Проверка** — запускаю проверки из раздела 3 и дописываю действия и результат в раздел «Фактическая проверка» той же спецификации.

## 5. Коммиты
- Формат: `feat: …`, `fix: …`, `docs: …`. В теле — зачем сделано изменение.
- Коммиты делает только человек. Агент может предложить текст сообщения.

## 6. Ограничения агента
Каждое правило проверяется по diff.

| Правило | Как проверить по diff |
| --- | --- |
| Не ставить и не удалять пакеты без одобрения | `package.json` и `package-lock.json` не изменены |
| Не читать и не менять файлы `.env*` | в diff нет `.env*`; содержимое env не появляется в коде и логах |
| Не менять схему базы без новой миграции | изменения схемы — только новым файлом в `supabase/migrations/`; существующие миграции не изменены |
| Не делать `git commit`, `push`, `revert`, `reset` | история коммитов не меняется агентом; изменения остаются незакоммиченными |
| Не менять `.github/workflows/` без запроса | файлы в `.github/workflows/` не изменены |
| Цвета, размеры шрифта и радиусы — только токены из `app/globals.css` | в компонентах нет `#hex`, `rgb(`, `text-[…px]`, `rounded-[…]`, inline `style` с такими значениями; новые значения — сначала токеном в `@theme` |
| Отметки приёма лекарства не удаляются и не перезаписываются | для отметок только добавление новой записи или пометка «отменено»; нет `delete` и `update` полей времени и автора отметки |
| Вызов API модели — только на сервере | обращения к модели и ключи — только в `app/api/**`; нет их в файлах с `"use client"` и в `components/` |
